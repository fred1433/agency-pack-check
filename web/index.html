    Reporting basis

    From the figures to the words

    Claude receives the approved figures of one snapshot, each with a reference, and writes the commentary with references instead of numbers. The code prints the values. The checker then reads every sentence: for each figure, the words around it must name the right measure, client, period and comparator, and say the right direction. What it cannot tie to a figure (a cause, advice, a general remark) goes to the reviewer, never to a tick.

    Built to sit around your process

    This prototype demonstrates explicit metric definitions, frozen evidence, claim checks, unresolved accounting questions and approval controls. It is designed to fit around your reporting process, not replace Xero, Syft or Claude.

    It is a synthetic prototype: the Xero adapter reads responses in the shapes Xero documents (Reports/ProfitAndLoss, Reports/TrialBalance, Budgets, Invoices, CreditNotes, ManualJournals, Organisation, TrackingCategories, Accounts), but it has not been run against a Xero organisation. No journal stream is needed: Journals is a premium endpoint from Xero's Advanced tier.

    Read-only scopes for a new app: accounting.reports.profitandloss.read, accounting.reports.trialbalance.read, accounting.invoices.read, accounting.budgets.read, accounting.settings.read. A Custom Connection serves one organisation, which can be a client's. Xero's terms forbid training models on API data.

    Only figures, labels and client names reach the model, never transactions, staff or bank details. Anthropic does not train on API content; standard API retention is up to 30 days, zero retention by agreement. The drafts here were produced on and frozen: this page replays them and calls no model.
